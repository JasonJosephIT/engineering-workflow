1. Current state

  • Python owns the loop. factory tick claims tickets, launches one worker per ticket worktree, re-runs gates.sh, merges into an integration branch, enforces caps and holds high-risk work for approval.
  • Two runners: Orca (default) and Agent Orchestrator, which uses an hourly launchd job and an orchestrator session that relays NEEDS YOU messages.
  • New on main: one climb worker after every ticket merges, then the final review, then factory queue moves to the next feature.
  • Evidence so far: Orca has one live run, AO a two-ticket dry run. Climb and queue ran against the fake Orca only (STATUS, 2026-11-04).

4. Integration considerations for Agent Orchestrator

  • macOS only. The heartbeat is hourly launchd, a backstop behind worker reports, so a dead worker can sit for an hour.
  • AO owns worktrees. The factory finds them by claim branch, so AO must keep one worktree per branch.
  • The brief forbids AO's PR workflow; nothing enforces it.
  • The bypass check reads two project-config keys (:180-181).
  • Unknown from this repo: AO's JSON contracts across versions, and whether ao spawn works under launchd's PATH. Record the tested AO version in state.

5. Validation plan

  1. Unit tests with the fake runners, one failing test per fix first. Report returns in under 1 s while the tick lock is held. The daily cap holds across advance. Two individually green tickets that break together are stopped. A climb with no metric gain or a changed harness is held. A silent reviewer is capped.
  2. Contract check. factory doctor against real Orca and AO.
  3. Live AO run on a throwaway repo. Two tickets, a climb.md and one queued feature, with a 3-minute gate, daily_ticket_cap 2, one forced NEEDS YOU and one heartbeat-only tick. Pass: nothing interrupted, cap holds, message arrives, score recorded by code.
  4. Release. Full tests, verify --expected 0.5.0, freeze, then a fresh session shows ew-hill-climb.
