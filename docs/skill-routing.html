Skill routing, add-ons & the EW dashboard

design · grilled 2026-10-28branch feature/skill-routingships after factory mode (v0.3.0)

EW will say which of your other skills to use at each stage, use them only when installed, install them as add-ons, keep domain packs out of every session, and give you a ticket-first dashboard.

2 · Add-ons, packs and what stays global

Add-ons · workflow.py addon

install · list · remove — pinned and verified like EW skills

  • graphify
  • multi-model-review (own private repo)
  • codebase-explainer
  • ew-flightdeck (Claude only)

Domain packs · workflow.py pack

add · remove — linked into one project only

  • web-design: awwwards ×5, cast/bunshin/paint, clone-website, extract-design, dembrandt, generate-ui-from-brand
  • output-engine
  • personal: brag-slim, resumes, financial-insights, payment credential, link identity

Global (outside EW)

  • frontend-team
  • graphify
  • watch-lite / watch-plus

Everything else is an ew- skill, an add-on, or a pack.

3 · ew-flightdeck

A fork of FlightDeck (MIT) as an add-on. It shows in the terminal and in the desktop app's Code tab, but not on your phone over Remote Control.

PanelChange
mainkeep: model, context, cost, rate limits
architectkeep; EW reviewers count as the architect
ticketsnew: tickets in progress across every session and project, each with its agents and permission checks (replaces agents + gate)
last promptnew: time since your last prompt
log · loops · receiptremoved

Source: EW hooks write one small JSON file per active ticket into EW's local state folder; the mod re-reads them on a timer. Factory mode uses the same files.
