How it flows

The dashed line means only local agents, via graphify explain or graphify path. Cloud agents read the committed overlay.

Overlay options

A. Thin overlay recommended

Commit only docs/map/. MAP.md lists the hubs and their files, god nodes, entry points, and the commit it was built from. Big communities get a short page each.

+ Small diffs. Works in the cloud. Easy to migrate.

− Cloud agents can't run path or explain queries.

About half a day.

B. A + inline marks

Also writes generated blocks into GLOSSARY.md and the ADRs, between <!-- graph:begin --> and <!-- graph:end --> markers. Each block lists which files a term or decision touches. Hand-written text isn't touched.

+ Docs and code stay linked.

− Generated text inside hand-written files. Only useful once a glossary exists.

About 2 more hours.

C. No repo files

Everything stays in the central store, and agents query it through the CLI.

− Breaks cloud sessions and other agents. Not recommended.

Migration per project

  1. Move graphify-out/ to the central store and add it to .gitignore.
  2. Run workflow.py graph and commit docs/map/.
  3. In WORKFLOW.md, change "read the graph first" to point at docs/map/MAP.md.

A full /graphify run with docs, papers and images still works. It just writes to the central store, and the overlay picks up the result.
